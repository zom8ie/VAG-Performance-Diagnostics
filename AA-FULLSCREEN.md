# Полноэкранная панель Android Auto: как это сделано

Статус: единственный вид панели в обеих сборках. Проверено в Desktop Head Unit
с профилем 800×480 (`build/dhu/yeti-6_5in.ini`), пакет тестовой сборки `ru.yeti.diag.dhu`.
Боевой пакет `ru.yeti.diag` не переустанавливался: категория и разрешения поверхности
объявлены в общем манифесте, но попадут в машину только после релиза и переустановки
привычным доверенным способом.
Состояние зафиксировано 17 ноября 2026: 537 автоматических проверок, вид и жесты
подтверждены снимками DHU. Это стартовая точка следующих чатов: продолжай с неё,
не возвращай удалённые виды и прежнюю сетку.

## Почему обычных шаблонов недостаточно

- `GridTemplate` и `PaneTemplate`: размер ячеек и изображения задаёт магнитола.
  На 800×480 сетка остаётся мелкой, а общее изображение панели кадрируется по области хоста.
- Плавающие кнопки сетки хост не рисует, если у экрана нет шапки; заголовок в плавающую
  кнопку добавлять нельзя — шаблон отклоняется.
- Произвольно рисовать на весь экран разрешено только на поверхности карты
  в навигационных шаблонах.

## Что нужно для полноэкранной поверхности

1. Категория службы `CarAppService` в intent-filter: `androidx.car.app.category.NAVIGATION`.
2. Разрешения в манифесте: `androidx.car.app.ACCESS_SURFACE` и
  `androidx.car.app.NAVIGATION_TEMPLATES`. Без них хост бросает `SecurityException`.
3. Шаблон `NavigationTemplate` из пакета `androidx.car.app.navigation.model`.
   `ActionStrip` обязателен (минимум одно действие): в нём остаётся один значок номера
   страницы. Размер и положение кнопки задаёт хост, приложение управляет только рисунком
   внутри — сейчас это мелкая приглушённая цифра «1/3». `MapTemplate` требует Pane или
   ItemList; пустой список хост рисует как «No items» и отдаёт ему половину экрана.
4. Регистрация колбэка поверхности: в `Screen.onStart` вызвать
   `getCarContext().getCarService(AppManager.class).setSurfaceCallback(callback)`.
   Метод называется `getCarService(Class)`, не `getCarAppService`.
5. Отрисовка: `SurfaceContainer.getSurface()`, `lockCanvas(null)`, рисование,
   `unlockCanvasAndPost(canvas)`. Хост показывает весь буфер целиком: рисовать нужно
   по всей площади канваса, а не только по прямоугольнику `onVisibleAreaChanged` —
   иначе остаются чёрные поля сверху и по бокам.
6. Нажатия: `SurfaceCallback.onClick(x, y)` приходит в координатах поверхности.
   Двойной тап хост перехватывает сам и присылает вместо двух кликов
   `onScale(focusX, focusY, 2.0)` — этим и открывается увеличение карточки.
   Долгого тапа в API поверхности нет: только одиночные клики без длительности.

## Управление панелью

- Тап по любой из двух правых карточек — следующая страница, по любой из двух левых —
  предыдущая. Страницы ходят по кругу; средние карточки страницы не листают.
- Двойной тап по любой карточке (`onScale` с фокусом в ней) — прибор на весь экран.
  Одиночный тап в режиме большого прибора возвращает панель 3×2.
- Значок номера страницы в системном углу тоже листает вперёд: шаблон навигации
  требует хотя бы одно действие, убрать его совсем нельзя. Цифра внутри сделана мелкой
  и приглушённой; сам кружок кнопки уменьшить или убрать нельзя — его размер фиксирует хост.
- Кнопок переключения видов нет: виды 1–3 удалены, панель одна.

## Как это устроено в проекте

- `DashboardSurface` — реализация `SurfaceCallback`: отрисовка кадра, передача кликов
  и жестов масштаба. `lockCanvas` обёрнут в защиту от `IllegalArgumentException`:
  хост может объявить поверхность раньше, чем готов её дисплей, а после краша процесса
  объявляет её снова при каждом перезапуске — без защиты получается вечный цикл крашей.
  Неудачный кадр пропускается и повторяется до трёх раз через 150 мс.
- `DashboardCarScreen` — `computeFrame()` считает значения и положения шкал; кадр рисуется
  прямо в поверхность, минуя ограничение хоста на частоту шаблонов. Анимация шкал:
  `DashboardNeedle`, 600 мс. `zoom` хранит номер увеличенной карточки, `-1` — вся панель.
- `DashboardTouch` — чистая математика жестов: прямоугольник панели внутри поверхности,
  номер ячейки по координатам тапа, направление страницы по столбцу, круговой сдвиг страниц.
  `reading()` делит отображаемое показание на число и единицу для двухстрочной подписи шкалы.
  Проверяется без телефона в `tests/DashboardTest.java` и в обоих кнопках анализа
  (`AnalysisRunner.checkDashboardPresentation`, запись `android_auto_gesture_motion`).
- `DashboardGauge.drawPanel()` масштабирует панель 3×2 в прямоугольник, сохраняя
  круглые дуги; `drawSingle()` рисует один прибор на всю поверхность. Внутри шкалы единица
  выводится маленькой строкой над крупным значением по центру, минимум и максимум стоят
  у концов дуги, подпись параметра — под шкалой; так же и в увеличенном приборе.
- `inputLocked()` игнорирует нажатия первые 500 мс после старта экрана: тап, который
  переключил экран, иначе «пробивает» на новую поверхность и сразу срабатывает ещё раз.

## Грабли, на которые уже наступили

- `Pane` без единого `Row` → `IllegalStateException` при сборке шаблона.
- Заголовок у плавающего действия сетки → `IllegalArgumentException`.
- `NavigationTemplate` и `MapTemplate` лежат в `androidx.car.app.navigation.model`.
- `SharedPreferences.apply()` может не дойти до диска до краша процесса: настройка
  «откатывается», хотя код её записал.
- После краша хост показывает экран ошибки до `am force-stop com.google.android.projection.gearhead`.
- `lockCanvas` бросает `IllegalArgumentException`, если поверхность объявлена, но ещё
  не готова, либо уже умерла вместе со старым процессом. Проверки `isValid()` мало.
- После `force-stop` только приложения хост иногда отдаёт мёртвую поверхность навсегда:
  кадр не рисуется, пока не перезапустить хост (`gearhead`) и DHU. В проверках ниже
  перезапускать оба, иначе панель будет чёрной без всякой ошибки.
- Значок `ActionStrip` DHU рисует справа сверху и он перекрывает верхний правый прибор.
  Это цена обязательного действия навигационного шаблона.
- Пустой `ActionStrip` у `NavigationTemplate` → краш при сборке шаблона: нужно минимум
  одно действие, совсем без кнопки панель не живёт.
- `setBackgroundColor` у действия полосы навигации → `IllegalArgumentException`:
  фон разрешён только primary-действиям, а в полосе навигации их нет.
- Действие только с заголовком, без значка, рисуется такой же тёмной пилюлей обычного
  размера: текст кнопкой не уменьшается.
- Хост фиксирует размер кружка кнопки и масштабирует содержимое значка под него:
  уменьшение битмапа (например до 28 dp) не меняет кнопку на экране. Уменьшить можно
  только глиф внутри — поэтому номер страницы рисуется мелким приглушённым текстом.

## Проверка без машины

1. `./test.sh` — 537 автоматических проверок, включая жесты страниц, деление показания
   на число и единицу и движение шкал.
2. `YETI_BUILD_VARIANT=debug YETI_APK_OUT="$PWD/build/yeti-diagnostics-dhu-0.18.0.apk" ./build.sh`.
3. `adb install -r build/yeti-diagnostics-dhu-0.18.0.apk` (отдельный пакет, боевой не заменяется).
4. `am force-stop ru.yeti.diag.dhu` и `am force-stop com.google.android.projection.gearhead`,
   затем запустить `desktop-head-unit -c build/dhu/yeti-6_5in.ini -u <серийный номер телефона>`;
   команды в stdin: `tap X Y`, `screenshot <абсолютный путь>`, `keycode back`.
5. Панель открывается сразу при запуске приложения в DHU.
6. Проверено нажатиями: двойной тап по средней карточке увеличивает её на весь экран,
   одиночный тап возвращает панель; тап по правой карточке листает вперёд, по левой — назад;
   демонстрационные показания движутся, шкалы анимируются.

## Что осталось решить

- Релиз с категорией `NAVIGATION`: панель появится в машине, но боевой пакет потребуется
  переустановить привычным доверенным способом, иначе Android Auto его не примет.
- Реальная магнитола может отличаться от DHU: частота кадров поверхности, поведение
  двойного тапа и области видимости требуют проверки на месте.
